# Видео-демо ChurnRadar

Скрипт сам проходит панель в Chromium и записывает видео по всему функционалу: субтитры
с пояснениями внизу экрана, глава в правом верхнем углу, подсветка элемента, о котором идёт
речь, и нарисованный курсор (в headless-режиме настоящего курсора на видео не видно).

На выходе в папке `OUT`:

| Файл | Что это |
|---|---|
| `demo.mp4` | видео 1440×900, H.264, главы зашиты в контейнер |
| `demo.srt` | те же субтитры отдельным файлом |
| `chapters.txt` | таймкоды глав в формате YouTube (`00:00 Вход`) |
| `raw.webm` | исходник от Playwright |
| `timeline.json`, `report.json` | субтитры и главы в миллисекундах, итог по сценам |

## Сцены

1. Заставка и вход (форма, кнопки SSO, если включены).
2. Обзор: радар, тёмная тема и на пару секунд светлая.
3. Обзор: KPI и как считается ожидаемая потеря.
4. «С кем связаться сегодня»: письмо первому клиенту, превью, отправка и это письмо в Mailpit.
5. Рассылка по очереди: только предпросмотр, без отправки.
6. Графики и причины: факт и прогноз, гистограмма, клик по причине → отфильтрованные клиенты и панель причины.
7. Клиенты: фильтр, сортировка, поиск, карта «риск × потеря».
8. Карточка клиента: причины, водопад оценки, деньги, баланс по дням, что сделать.
9. Отчёт PDF (скачивается в `OUT`).
10. Маркетинг: MRR, ARPU, LTV, удержание, графики, словарь.
11. Модель и «Что если»: двигаем вес, «было → станет», «Отменить».
12. Живой пересчёт: настоящий PATCH веса и сразу обратно, история изменений.
13. Качество модели: lift, ROC AUC, Brier и надёжность, сравнение с правилами.
14. Сценарии удержания: заготовки и предпросмотр нового сценария, без сохранения и боевого режима.
15. Уведомления: настройки, тестовое уведомление, колокольчик.
16. Источники данных: коннекторы и Метрика, только просмотр.
17. Интеграции (без выпуска токенов) и журнал действий.
18. Пользователи и роли: окно нового пользователя без создания.
19. Вход через Authentik (OIDC, если выключен — SAML).
20. Демо-пульт по Shift+D.
21. Grafana, дашборд «Отток».
22. `/metrics` в виде терминала (если задан верный `METRICS_TOKEN`).
23. Слайд «Что под капотом» и финальный кадр.

Если страницы или элемента в сборке нет, сцена пропускается с записью в лог, запись идёт
дальше. Итог по сценам печатается в конце и лежит в `report.json`.

## Что скрипт меняет на стенде и как возвращает

- Письмо клиенту действительно уходит через SMTP. После записи письмо удаляется из Mailpit,
  а клиенту возвращается прежний статус.
- Вес признака меняется по-настоящему (так виден пересчёт) и сразу же возвращается обратно.
  Если запись оборвалась, прежнее значение ставится через API в конце.
- Тестовое уведомление удаляется из Mailpit. Запись под колокольчиком остаётся: это обычное
  уведомление администратора.
- Если учётка SSO (`marketer`) появилась только из-за входа в видео, она удаляется.
- Рассылка, новый сценарий удержания и новый пользователь только открываются, ничего не сохраняется.
  Данные, симулятор и коннекторы скрипт не трогает.

## Как записать локально

Нужны Node.js 22.6+ и ffmpeg. Если ffmpeg нет, скрипт возьмёт его из docker-образа
`jrottenberg/ffmpeg` (можно сменить переменной `FFMPEG_IMAGE`).

```bash
docker compose --profile sso up -d       # стенд, профиль sso — по желанию
cd tools/demo-video
npm ci
npx playwright install chromium          # если браузер ещё не скачан
npm run record                           # результат в tools/demo-video/out
```

Отдельные сцены для отладки и быстрый темп:

```bash
SCENES=marketing,what-if PACE=0.5 HEADLESS=0 npm run record
```

Пересобрать mp4, srt и главы из уже записанного `raw.webm`:

```bash
OUT=out npm run encode
```

## Как записать на проде

На проде Mailpit живёт под `/mailpit/` и закрыт basic auth, Grafana — под `/grafana/`.

```bash
BASE_URL=https://churn.example.ru \
ADMIN_USERNAME=admin ADMIN_PASSWORD='...' \
MAILPIT_URL=https://churn.example.ru/mailpit MAILPIT_USER=mailpit MAILPIT_PASSWORD='...' \
GRAFANA_URL=https://churn.example.ru/grafana GRAFANA_USER=admin GRAFANA_PASSWORD='...' \
METRICS_TOKEN='...' SSO_MARKETER_PASSWORD='...' \
OUT=./out-prod npm run record
```

Пароли берутся из `.env` на сервере (его пишет `deploy/prod/install.sh`) и передаются только
переменными окружения при запуске. В репозиторий и в файлы рядом со скриптом их не кладём.

## Переменные

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `BASE_URL` | `http://localhost:8080` | адрес панели |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | `admin` / `admin` | вход администратора |
| `MAILPIT_URL` | `http://localhost:8025` | почтовый ящик стенда |
| `MAILPIT_USER`, `MAILPIT_PASSWORD` | — | basic auth Mailpit на проде |
| `GRAFANA_URL` | `http://localhost:3000` | Grafana |
| `GRAFANA_USER`, `GRAFANA_PASSWORD` | `admin` / `admin` | вход в Grafana |
| `METRICS_TOKEN` | `churn-metrics-demo-token` | токен `/metrics` |
| `SSO_USERNAME`, `SSO_MARKETER_PASSWORD` | `marketer` / `marketer` | учётка Authentik для сцены SSO |
| `OUT` | `tools/demo-video/out` | куда класть результат |
| `SCENES` | все | только эти сцены, через запятую (`login` идёт всегда) |
| `PACE` | `1` | множитель пауз: `0.5` — вдвое быстрее |
| `HEADLESS` | `1` | `0` — смотреть запись в окне браузера |
| `SKIP_ENCODE` | — | `1` — не собирать mp4 |
| `FFMPEG`, `FFMPEG_DOCKER`, `FFMPEG_IMAGE` | — | свой путь к ffmpeg или принудительно docker |

Id сцен: `intro`, `login`, `design`, `overview`, `contact-today`, `campaign`, `charts`,
`customers`, `customer`, `report`, `marketing`, `what-if`, `recalc`, `quality`, `playbooks`,
`notifications`, `data`, `integrations`, `users`, `sso`, `demo-panel`, `grafana`, `metrics`,
`architecture`.

## Как устроено

- `record.ts` — сценарий и режиссура: фраза показывается, пока идут действия, следующая
  ждёт, пока предыдущую дочитают (время чтения считается по длине текста).
- `overlay.ts` — слой поверх страницы: субтитры, глава, затемнение с рамкой вокруг цели,
  курсор и круги кликов. Ставится через `addInitScript`, переживает переходы между страницами
  и работает на чужих страницах (Mailpit, Authentik, Grafana). Если цель внизу экрана,
  субтитры уезжают наверх, чтобы её не закрывать.
- `slides.ts` — HTML-слайды на `data:`-страницах: заставка, терминал с `/metrics`, архитектура.
- `encode.ts` — webm → mp4 (H.264, главы в метаданных), `demo.srt`, `chapters.txt`.
